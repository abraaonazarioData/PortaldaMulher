3. Detalhamento Técnico das Correções Realizadas

3.1. Sanitização do Repositório Git (SEC-01)

Problema Diagnosticado: O banco de dados físico db.sqlite3 estava commitado no repositório. Isso representava vazamento de senhas com hash PBKDF2 e dados sensíveis para qualquer usuário com acesso ao repositório.

Ação Realizada: O arquivo foi desvinculado do índice do Git sem exclusão local (git rm --cached) e as exclusões de *.sqlite3, db.sqlite3, .env e .secret_key foram registradas no .gitignore.

# Regras aplicadas no .gitignore *.sqlite3 db.sqlite3 *.db .env *.env .secret_key

3.2. Blindagem de Chaves Criptográficas e Headers no settings.py (SEC-02 e SEC-05)

Problema Diagnosticado: Se a variável de ambiente não existisse, a aplicação utilizava uma chave padrão estática django-insecure-..., permitindo potencial falsificação de sessões e cookies administrativos. Além disso, faltavam cabeçalhos contra MIME sniffing e clickjacking.

Ação Realizada: Implementou-se um gerador criptográfico local baseado em secrets.token_urlsafe(50) com suporte a carregamento nativo de variáveis de arquivo .env e definição dos cabeçalhos recomendados.

import secrets # Geração dinâmica segura caso não informado no ambiente SECRET_KEY = os.environ.get('DJANGO_SECRET_KEY') if not SECRET_KEY: _key_file = BASE_DIR / '.secret_key' if _key_file.is_file(): SECRET_KEY = _key_file.read_text(encoding='utf-8').strip() else: SECRET_KEY = secrets.token_urlsafe(50) _key_file.write_text(SECRET_KEY, encoding='utf-8') # Cabeçalhos Globais de Defesa SECURE_CONTENT_TYPE_NOSNIFF = True SECURE_BROWSER_XSS_FILTER = True X_FRAME_OPTIONS = 'DENY' SESSION_COOKIE_HTTPONLY = True SESSION_COOKIE_SAMESITE = 'Lax' CSRF_COOKIE_SAMESITE = 'Lax'

3.3. Neutralização de Stored XSS nos Templates (SEC-03)

Problema Diagnosticado: As páginas index.html, modulo4_mapa_rede.html e atendimentos.html inseriam dados em JavaScript usando var allLocations = {{ redes_json | safe }};. A tag |safe desativa a proteção contra tags </script>, permitindo execução de código JavaScript malicioso cadastrado no banco.

Ação Realizada: A injeção foi substituída pela tag segura oficial do Django {{ redes|json_script:"id" }}, com recuperação estrita via JSON.parse().

<!-- Template Seguro (index.html / modulo4_mapa_rede.html / atendimentos.html) --> {{ redes|json_script:"home-redes-data" }} <script> var allLocations = JSON.parse(document.getElementById('home-redes-data').textContent); </script>

3.4. Restrição de Uploads de Vetores SVG (SEC-04)

Problema Diagnosticado: O modelo PageContent.image permitia arquivos .svg, que são documentos XML e podem conter scripts embutidos executados no navegador ao serem visualizados.

Ação Realizada: O validador do Django em core/models.py foi restrito a formatos rasterizados seguros: ['jpg', 'jpeg', 'png', 'webp', 'gif'].

5. Conclusão e Recomendações Futuras

Com as intervenções aplicadas, o projeto Portal da Mulher MT encontra-se protegido contra os principais vetores de invasão em camada de aplicação (vazamento de credenciais via Git, sequestro de sessões, Stored XSS e manipulação de arquivos).

Para o ciclo contínuo de manutenção, recomenda-se:

  • Efetuar a rotação das senhas dos administradores cadastrados na base local.
  • Em ambiente de produção de grande porte, adotar um proxy reverso Nginx/Caddy para terminação SSL em substituição ao proxy socket Python.
  • Manter a dependência django-ckeditor no radar para migração futura para o django-ckeditor-5.
